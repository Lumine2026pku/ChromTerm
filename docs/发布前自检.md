# ChromTerm 发布前自检（GitHub Pages）

> 2026-11-02　对象：本仓库要发布到 GitHub Pages 的那一份（`index.html + assets/ + examples/`）
> 结论：**可以发布**。静态模式下页面能完整跑通：识别模型加载 → 单末端推理 → 结论渲染；
> 整片照片、空白图、TIFF 三条分支都实测过。

## 一、怎么验的（以及一个限制）

本机沙箱禁止浏览器启动（Edge 的 mojo 命名管道被拒），所以**没有用真实浏览器截图**，
改为把 `assets/app.js` 用 Node 加载，配一个最小的 DOM / canvas / fetch 垫片，
完整走一遍页面自己的代码路径（读图 → `toCanvas` → `engine.analyze` → `render`）。

这样做的好处是：验证的是**页面真实代码**，不是另一份复刻实现；
尤其是"静态模式判定""模型 JSON 加载""结论渲染"这几段逻辑。
代价是 `ResizeObserver`、CSS 布局、SVG 绘制这些与视觉相关的部分没有覆盖到。

## 三、这一轮修掉的三个真实缺陷

1. **页头指标块陈旧**：`assets/model/model_best.json` 里内嵌的 `metrics` 只含 6 个字段，
   `test_ece` / `cv_f1` / `temperature` 是模型更新后才加进 `models/metrics.json` 的。
   已扩展导出脚本，14 项现在完全一致（见 `tools/export_web_model.py`）。
2. **页脚文案误导**：原来写「指标来源 models/metrics.json」，但 `models/` 不在 Pages 发布包里，
   真正读到的是模型 JSON 内嵌的 `metrics`。已改成「指标随模型文件分发」。
3. **导出脚本依赖 `_cache/`**：仓库发布版不带数据集与缓存，`tools/export_web_model.py`
   会直接崩。已加降级路径：找不到缓存时沿用上一版 JSON 的 `geo_mean` 并**明确告警**。
   （几何块对准确率贡献≈0，实测去几何 0.4587 vs 全特征 0.4593，所以这个降级是可接受的。）

## 四、静态模式的已知边界（不是缺陷，是设计）

* 没有后端 → **没有「整片多末端」**（按钮禁用、`setMode('multi')` 会被拦下）；
* 不做几何量测（长度 / 臂宽 / 端部朝向），只给类别 + 6 类概率 + 短名单；
* 图像只在浏览器内存里处理，不上传；
* 推理耗时（Node 垫片实测）：端部小图 ~90 ms，1600×1335 整片 ~140 ms。

## 五、发布方式

**A. GitHub Actions（推荐，仓库已配好）**
Settings → Pages → Source 选 **GitHub Actions**；推送到 `main` 后，
`.github/workflows/pages.yml` 只把 `index.html + assets + examples` 收进 `_site`。

**B. Deploy from a branch**
根目录已有 `index.html` 与 `.nojekyll`，可直接用；`docs/*.docx` 会一并被托管（无害）。

无论哪种方式，**都不要把 `_cache/`、`data_share/`、`runs/` 打包进去**
（单文件上限 100 MB，而 `level1_features.npz` 有 165 MB）。

## 六、复现自检

```bash
python tests/test_smoke.py            # 或 pip install pytest && python -m pytest -q
python tools/profile_stats.py         # 采样的同口径校验（需要 _cache/）
```

页面级自检（本仓库外的工具目录）：
```bash
node ../_tools/app_sim.mjs <工作区根> term    # term | tiff | photo | blank
```
