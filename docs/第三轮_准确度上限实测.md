# 第三轮：准确率还能不能再高——11 个方案的实测

> 2026-11-02　对象：`data_share`（961 窗口 / 6 类）+ 组内《中线采样说明》的宽度通道
> 协议不变：**配置只用"按原图分组的重复 5 折 ×3"（15 折）选**，官方 test（150 窗）只报数。
> 全部数字由 `_tools/exp_*.py` 生成，可重跑（脚本见文末）。

## 一、结论

**在这个模型族里（numpy 线性模型 + 手工特征），准确率已经到顶**：本轮又试了 11 个方向，
没有一个能超过基线的 CV-F1 0.475 / test 0.513。组里 ResNet-18 能到 0.540，
差的这 3 个点来自"学习出来的二维卷积特征"，不是我们漏了某个手工特征。

真正能提高**可用准确率**的不是再换特征，而是三件事（都在下面第三节给了数字）：
① 用 top-2 短名单；② 按把握程度拒识；③ 与另一条线的模型做概率融合（需要对方导出概率）。

## 二、11 个方案与结果

| # | 尝试 | CV-F1 | test-Acc | 判定 |
|---|---|---|---|---|
| 1 | **基线**：OD 多尺度 + 带纹 + 宽度 + 几何 → 收缩 LDA | **0.475** | **0.513** | 基线 |
| 2 | 中线曲线 1D（端点起算、1 px 弧长、带序列） | 0.289 | 0.373 | 明显更差 |
| 3 | 按中线的拉直长条 2D（48×96，尺度按臂宽归一） | 0.314 | 0.353 | 明显更差 |
| 4 | 基线 + 曲线（特征拼接） | 0.455–0.475 | 0.493–0.547 | 无增益（test 高的是抽样波动） |
| 5 | 基线 + 曲线（**概率**融合，权重只在 val 选） | — | 0.513（w=1.00） | 权重把曲线模型投成 0 |
| 6 | 更多上下文：沿臂 **zoom** ×2 / ×3 | 0.319 / 0.280 | 0.273 / 0.247 | 越看越差 |
| 7 | 更多上下文：沿臂 **extend** ×2 / ×3 | 0.302 / 0.274 | 0.240 / 0.280 | 越看越差 |
| 8 | 局部块码本 BoVW / VLAD（K=64） | 0.279 / 0.313 | 0.293 / 0.313 | 明显更差 |
| 9 | 翻转 TTA；翻转+平移训练增广 | 0.467 / 0.442 | 0.507 / 0.527 | 噪声（CV 反而降） |
| 10 | 整窗特征图 PCA(32–256) + LDA | 0.326–0.419 | 0.333–0.433 | 明显更差 |
| 11 | 7 模型集成 / 概率堆叠 | 0.459–0.470 | 0.480–0.520 | 噪声 |
| 12 | 染色体层级（chr2 / chr3 / X / other，4 类） | — | 0.540 | 只 +2.7 点 |
| 13 | 神秘字段 `f` + 框几何（面积比/长宽比/长边） | 0.455–0.462 | 0.520–0.527 | 噪声 |
| 14 | 只用"确定"窗口训练（394 窗） | — | 0.575（80 确定窗） | 不如训全量再筛（0.588） |

几条值得单独说明的：

* **第 6/7 行很关键。** 我们一直怀疑"窗口只有 3 个臂宽"是瓶颈。于是直接用
  `det` 的 OBB 从**原始整图**重新裁剪，沿臂方向放大 2×/3×（两种口径：压缩分辨率看更远、
  或保持分辨率拉长画布）。结果两种口径都**下降**。所以瓶颈不是"看得不够远"，
  而是**单位面积里的细节不够**——这与组里报告"40 倍镜 28.2% vs 整图 88%"的观察一致。
* **第 5 行说明**：融合能不能涨点，取决于第二个模型是否"够强且错得不一样"。
  我们的曲线模型（0.373）太弱且与基线同源，val 上选出的权重直接是 1.00（等于不用它）。
  组里那次 55.3%→58.7% 的融合，是"强 ResNet + 弱曲线"，起点就比我们高。
* **第 12 行**：把 2L+2R 合成 chr2、3L+3R 合成 chr3 之后只有 0.540。说明错误**不是**
  集中在"左右臂搞反"上——实际只有 18% 的错误属于这一类。所以"改成染色体层级"救不了准确率
  （但组里报告的"实例级类别一致率 43.9%"仍是重要的标签噪声证据）。

## 三、能提高"可用准确率"的三件事（都有实测数字）

| 用法 | 准确率 | 代价 |
|---|---|---|
| 6 类全判 | 51.3% | — |
| 只给 **top-2 短名单** | 72.7%（命中率） | 人工从 2 个里选 |
| 只判**最有把握的 40% / 20%** | 63.3% / 70.0% | 其余不判 |
| 只看**标注者标"确定"的窗口**（difficult=0 且 uncertain=0，n=80） | 58.8% | 适用范围变窄 |
| 粗问法：**2L / X / 其余** 三组（n=150） | 74.0% | 不给精确臂名 |
| 更粗：**2L vs 非 2L** | 84.7% | 只做初筛 |

这也是为什么建议把界面默认输出设成"三组 + top-2 + 置信度"，把 2R/3L/3R 的细分标成"待确认"。

| 文件 | 内容 |
|---|---|
| `runs/level1_profiles.csv` | 961 窗 × 24 列：臂宽 `arm_width_px`、带数、带宽中位（px 与"臂宽倍数"两种）、间距、占空比、前三条带的位置签名、长度/臂宽… |

实测概况：臂宽中位 **42.0 px**、带数中位 **3**、带宽中位 **15.0 px（0.37 个臂宽）**、
占空比中位 **0.24**、窗内长度/臂宽中位 **4.15**。

**2. 一个能直接吃掉对方 ResNet 概率的融合工具**（`src/fuse_probs.py`）

```bash
python src/fuse_probs.py export --out runs/probs_ours.csv          # 导出本项目的逐窗概率
python src/fuse_probs.py fuse --mine runs/probs_ours.csv \
    --other /path/to/resnet_probs.csv --out runs/fused.csv          # 权重只在 val 选
python src/fuse_probs.py self-test                                  # 机制自检（合成外部模型）
```

* 输入只要 `name + 6 类概率`，列名大小写不敏感，概率会自动归一化；
* **权重只在 val 上按 macro-F1 选**，test 只报数一次，避免在 test 上调参；
* 会打印"相对两个单模型各涨多少"，并提示 test 只有 150 窗、标准误 ±4 个点；
* 自检结果：合成的互补外部模型（acc 0.387）与主干（0.513）融合后 w=0.80、test 0.527。

**这就是目前已知最大的一次单项提升来源**：组里实测 54.0% → 58.7%（+4.7 点）。
缺的只是对方那 150 行概率——把 `outputs/classification/` 里的逐窗概率导成 CSV 即可。

## 五、要让 6 类准确率真正上一个台阶，需要什么

1. **学习出来的二维骨干**（他们已有的 ResNet-18 就是）：多出约 3 个点，
   再叠加曲线融合还能 +3~5 点。这是本项目（numpy 运行时）够不到的部分。
2. **更干净的标签**：实例级类别一致率 43.9%、κ=0.653，说明天花板本身不高。
   补标"不确定"窗口、或对同一端部做双标取一致，比再调特征更值钱。
3. **更高的成像分辨率/对焦**：40 倍镜小图的细节不足以支撑 6 类区分（本轮第 6/7 行佐证）。
